# tavernpi

**一个以数据库为记忆的故事引擎。**

写作者输入角色的行动与对话，tavernpi 写出后续叙事，并记录发生的一切：谁在场、谁说了什么、时间过了多久、角色走到了哪里、与谁的关系发生了变化。

多数 LLM 写作工具的记忆就是聊天记录。tavernpi 在每一轮叙事结束后，从正文里抽出事实写进 SQLite。**对话历史是草稿，数据库才是事实。** 因此任意节点都能回溯、重新演绎、开出新分支，走错一步时不必重开。

当前版本 **v0.1.0**。

---

## tavernpi 解决什么问题

用 LLM 写长故事，通常会遇到三个问题：

1. **失忆**：写到第 50 轮，模型忘了主角住在哪、和谁翻过脸。上下文窗口容纳不下，塞进去的信息还会互相稀释。
2. **失控**：模型即兴编出的设定（"你妹妹其实早死了"）没有机制拦截，世界观会逐渐偏离。
3. **无法回头**：一个转折写坏了，聊天记录里没有撤销的余地，只能删掉重来，或者将错就错。

tavernpi 的应对方式：

| 问题 | 应对 |
|---|---|
| 失忆 | 长期记忆落 SQLite。每轮按需从库里召回相关事实注入，历史不必全塞进上下文 |
| 失控 | 独立的 subagent 从正文里**抽取**事实并落库；叙事模型无法直接改设定，它写出的内容要经校验才成为事实 |
| 无法回头 | 每轮结束拍一次数据库快照。回溯、重骰、分叉都从快照恢复，世界状态随之回退 |

## 一轮是怎么发生的

输入一行行动，触发的是一条流水线：

```
输入
  ↓
① 场景分析    读懂这一轮发生了什么、该召回哪些设定
  ↓
② 世界注入    从数据库捞出相关的人、地点、事件，连同卡包设定一起注入
  ↓
③ NPC 预演    在场的角色各自推演反应（并行），不在场的离线推演他们在别处做什么
  ↓
④ 主叙事      写出这一轮正文
  ↓
⑤ 润色（可选）  只改文风，不动任何事实
  ↓
⑥ 事实抽取    从正文里抽出状态变化，写入数据库 ← 唯一能改库的地方
  ↓
⑦ 拍快照      本轮末的数据库状态存档
```

几个设计上的关键点：

- **主叙事模型没有数据库写权限**。它的工具列表为空，改世界只能通过正文，而正文要经第 ⑥ 步的独立抽取才落库。这是"叙事会偏离设定"的工程解法。
- **第 ⑥ 步是唯一写者**。抽取失败就不拍快照，未落库的内容下一轮补齐，不会出现叙事已写出而世界未记录的静默不一致。
- **快照绑定在轮末**，所以回溯到第 N 轮会精确恢复第 N 轮结束时的世界，重做那一轮不会导致事件双重记账。

## 三种玩法模式

同一个引擎，三种定位。模式由**内核级强制**，不走界面开关，绕开界面也无法越权。

| | **创造** | **生存** | **冒险** |
|---|---|---|---|
| 定位 | 小说创作辅助 | 沉浸扮演 | 沉浸扮演 + 信息迷雾 |
| 输入 | 角色行动 + **剧情大纲指令** | 仅角色的行动/对话 | 同左，且更严 |
| 世界可见度 | 完全透明 | 完全透明 | **仅限角色经历过的** |
| 引擎 | story/npc/润色可关 | 只有润色可关 | 全部强制开启 |
| 换模式 | ↔ 生存，随时 | ↔ 创造，随时 | **创建时选定，之后锁定** |

冒险模式的数据库查询层会按"与角色相关"过滤：不相关的事件不进入上下文，没见过的角色不在查询结果里。这种信息迷雾由查询层实现，不依赖提示词约束模型的输出。

## 上手

前置：Node.js ≥ 24，`npm install`，并在 pi 的 `auth.json` 里配好模型 key。

```bash
# 开一个新故事
npm run cli

# 带世界设定（卡包）+ 生存模式
npm run cli -- --pack ./my_world --mode survival

# 续写（每次退出时 CLI 会把这行命令打印出来）
npm run cli -- --resume <session 文件路径>
```

命令行参数：`--pack <目录>`（可重复）· `--mode creation|survival|adventure` · `--style <文风>` · `--root <目录>`（故事数据目录，默认 `~/.tavernpi`）。

进入后**直接输入角色的行动或对话，回车即出一轮叙事**。空行退出。

### 命令

| 命令 | 作用 |
|---|---|
| `/tree` `/tree <n>` | 看故事树 / 跳到第 n 条（世界状态随之恢复） |
| `/fork <n>` | 从第 n 条分叉出一条新故事线 |
| `/swipe` | 重骰最后一轮（旧稿留在树上，不丢） |
| `/status` | 状态面板：时间、位置、模式、在场角色 |
| `/mode [模式]` | 查看 / 切换模式 |
| `/plot <大纲>` | 写剧情大纲，指导后续走向（仅创造模式） |
| `/compact` | 生成章节摘要，压缩会话 |
| `/assist <问题>` | 旁路顾问：问它问题，不影响故事本身 |
| `/packs` `/packs add\|remove` | 查看 / 装卸世界包 |
| `/pin` `/unpin` `/reload` | 固定条目（每轮必注入）/ 取消 / 重载世界包 |
| `/agents` `/models` `/prompt` | 子代理开关 / 各角色模型 / 提示词分层 |
| `/write <文件>` | 用变更集文件直接写库 |
| `/! <输入>` | 强制提交被拦下的输入（会留痕） |
| `/help` | 完整帮助 |

> 生存与冒险模式下，输入须为角色能做的事。强行推进剧情的输入（如"我命令卫兵开门"）会被拦下，用 `/!` 前缀可强制提交，引擎会记录这次越权。

## 世界包（卡包）

**一个世界包 = 一部作品的完整设定。** 它是普通目录，纯内容、零代码：

```
my_world/
├── package.json        # 包名即命名空间前缀
├── story.yaml          # 标题、历法、开场白、默认文风
├── collection/         # 设定集：一条目一文件，文件名即条目 id
│   ├── characters/     #   角色（主角与 NPC 同构）
│   ├── locations/      #   地点（可标层级与坐标，用于地图与距离推理）
│   ├── objects/        #   关键物品
│   ├── factions/       #   势力组织
│   └── plot/           #   剧情线
├── prompts/            # 可选：覆盖任意 subagent 的提示词
└── db/
    ├── schema.sql      # 自定义表
    └── seed.sql        # 种子数据
```

**SQL 是一等创作接口。** 需要一张"好感度"表，自行建表即可，无须等待引擎支持：

```sql
CREATE TABLE IF NOT EXISTS my_world_char_status (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  npc_ref TEXT NOT NULL,
  favor INTEGER NOT NULL DEFAULT 0,  -- favor: -100~100，初见通常为 0
  turn_seq INTEGER NOT NULL
);
```

字段注释即给抽取阶段的填写说明。此后每轮叙事产生的状态变化会被自动写进这张表。

工具链：

```bash
node packages/tools/src/cli.ts init ./my_world     # 生成骨架
node packages/tools/src/cli.ts check ./my_world    # 全量校验 + 内存库试跑 SQL
node packages/tools/src/cli.ts templates           # 内置 SQL 模板（角色状态栏 / 物品栏 / 任务进度）
```

`check` 会在干净的内存库里执行一遍建表与数据，验证幂等性，**在故事开始之前**抓出 SQL 错误、断链引用、表名漏前缀。卡包的一个笔误不会毁掉一段长故事。

卡作者文档：`packages/tools/README.md`。完整示例：`packages/app/acceptance/fixtures/shouling/`。

## 项目结构

```
packages/
├── core/     @tavernpi/core —— 引擎内核
│             轮次流水线 · 数据库层 · 快照 · subagent 体系 · 提示词分层
│             卡包加载 · 模式预设 · 视图过滤 · 会话装配
├── app/      CLI（npm run cli）· 验收脚本 · 探索性验证工件
├── tools/    @tavernpi/tools —— 卡包校验 / 骨架 / 模板 CLI
└── studio/   @tavernpi/studio —— GUI 外壳（Electron，同进程嵌入内核）
              S0 骨架已跑通；S1 起做界面
```

**内核与外壳的边界是硬约束**：所有故事引擎逻辑（流水线、subagent、快照、校验、模式）都在 `core/`。界面层只做呈现，不实现引擎逻辑；UI 侧绕过模式在架构上无法做到，因为过滤和校验位于查询层。这条边界由自动化测试扫描源码钉住，属于机器判据。

内核可作为库同进程嵌入：`@tavernpi/core`（CORE_VERSION 0.1.0）。对外 API 的收窄原则见 `packages/core/src/index.ts` 头部注释。
