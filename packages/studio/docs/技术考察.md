# tavern studio 实现考察

> 本文是 S0（技术选型）的考察结论，配合 `创作规划.md` 使用。
> 规划文档定义**做什么**（UX 契约），本文回答**怎么实现**（形态、契约、缺口、路线）。
> 所有结论附实测证据或代码出处；标注「实测」的条目在本机容器内真实跑过。

## 0. 结论摘要

| 问题 | 结论 |
|---|---|
| 形态选型 | **Electron**（Tauri 否决，见 §2）——不是偏好，是唯一闭合项 |
| 渲染层选型 | **React + Vite + TS**（生态件覆盖长流虚拟滚动/树/表格/表单；renderer 只经传输层说话，层 1 可脱 Electron 断言） |
| 传输层 | **从第一天就是可替换适配器**：生产 preload/IPC，开发本地 HTTP/SSE；共用 `packages/studio/src/contract/` 契约 |
| 仓库归属 | **与内核同仓库、独立包** `packages/studio`（API 定型 + 出现外部消费者后再拆仓） |
| 内核能否同进程嵌入 | **能，已实测**：主进程直接 import 内核 TS 源码（`CORE_VERSION 0.6.0`，96 个导出） |
| 故事库能否直接读 | **能，已实测**：`node:sqlite` 可用，读出真实 `turn_log` / 时钟 / 事件 |
| 渲染管线上线 | **能，已实测**：窗口 + DOM + WebGL + GPU 合成全绿（显示器 1536×960，niri/wayland） |
| 内核契约覆盖度 | **缺口 1–12 已全部补齐**：中止 / settings 写+thinking / 故事枚举 / 装配 API / 通用只读查询 / subagent 开关与钉持久化 / pipeline 成对事件（含阶段运行态）/ 卡包校验与新建可复用 / 提示词 global 层可写 / 运行期换包（`setPacks`）/ `DbView` 可见性惰性刷新——见 §3.2 与 §4.3 |
| 阅读流的唯一事实源 | **`story.db` 的 `turn_log`**，不是 session 转录（§3.3，这条决定 studio 的数据流设计） |
| 最大运营风险 | Electron 二进制与自动更新都走 GitHub，本机**直连不通**，必须镜像/自建（§5） |

## 1. 环境可行性（实测）

本机是 NixOS 宿主内的 distrobox 容器（Deepin 25），无 root、无 sudo。四条硬结论：

| 检查项 | 结果 | 证据 |
|---|---|---|
| Electron 二进制 | 可用，44.4.2 | `electron/dist/electron` 228 MB，`--version` → `v44.4.2` |
| 内置运行时 | Node **24.21.0** / Chromium 152 | `process.versions` |
| 内核 TS 源码直载 | 通过 | 主进程 `import core/src/index.ts` → `CORE_VERSION 0.6.0`，96 导出 |
| `node:sqlite` | 通过 | `typeof DatabaseSync === "function"` |
| 真实故事库读取 | 通过 | 读出 `turn_log`(1 行) / `clock` / `events`；正文 199 字 |
| 窗口 + 渲染 | 通过 | 隐藏窗口 DOM 文本 `tavern studio`、`webgl: true`、`gpu_compositing: enabled` |
| 显示后端 | wayland（niri）+ X11 兼容 | `/run/user/1000/wayland-1`、`/tmp/.X11-unix/X0`、`DISPLAY=:0` |
| GTK/NSS/GBM 依赖 | 齐备 | `libgtk-3.so.0` / `libnss3.so` / `libgbm.so.1` 均在 |

复现方式（本包内，`npm install` 一次即可）：

```bash
export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/   # 必须：见下
npm install                                                     # electron 44.4.2（228MB 二进制）

# 环境冒烟（隐藏窗口：内核直载 / node:sqlite / 窗口渲染三件事一次问清）
npm --workspace @tavernpi/studio run spike

# 开真窗口
npm --workspace @tavernpi/studio run start

# S0 收尾验收：空壳里真跑「列故事 → 新建 → 发一轮（真 LLM）」，主进程独立核对盘上 story.db
npm --workspace @tavernpi/studio run accept:s0
```

**两条环境坑（都实测踩过）**：

1. **Electron 二进制默认从 `github.com` 拉取，本机不通**（`curl -sI https://github.com/...` 超时；`npm install` 本身成功是因为走 npmjs registry）。首次安装直接 `TypeError: fetch failed` → `Electron failed to install correctly`。加 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`（可达，302）后正常。二进制若没下下来，可补跑 `ELECTRON_MIRROR=... node node_modules/electron/install.js`。
2. **本机默认导出 `ELECTRON_RUN_AS_NODE=1`**，Electron 会退化成纯 Node：窗口起不来、`--version` 打印的是 Node 版本（24.21.0 而非 44.4.2）、`import { app } from "electron"` 直接不可用。所有启动路径都带 `env -u ELECTRON_RUN_AS_NODE`——npm scripts 里已写死，手工敲命令时别忘。

次要噪声：容器内无系统 dbus socket，Electron 每次启动打 3 行 `Failed to connect to the bus`。实测不影响窗口/渲染/内核，属可忽略项（可经环境变量静音）。

类型剥离在 Electron 内同样生效：主进程入口可以直接是 `.ts`（实测 `main: "src/main/index.ts"` + `"type": "module"` 正常启动），故 studio 主进程与内核一样**不得使用不可擦除语法**（`enum` / `namespace` / 构造函数参数属性）——`tsconfig.base.json` 的 `erasableSyntaxOnly` 会当场拒绝。preload 例外：`sandbox: true` 下 preload 不支持 ESM，写成 `.cjs`。

## 2. 选型：为什么是 Electron

规划文档的硬约束是「**同进程嵌入 Node/TS 内核库，不走 RPC**」。以此为判据逐项排除：

- **Tauri 否决**：宿主是 Rust，进程内没有 JS/Node 运行时。要让内核跑起来只有两条路——(a) Node sidecar 子进程 + IPC，这是 RPC，直接违背已决策；(b) 嵌入 deno/替代 JS 运行时，而内核依赖 `node:sqlite`、`node:fs` 同步 API、pi SDK 的进程内 session 管理，deno 兼容层的风险与工作量都不可控。Tauri 的优势（包体小、Rust 安全边界）在「必须嵌 Node」这一条面前全部失效。
- **Electron 是唯一闭合项**：主进程就是 Node，内核是普通 npm 依赖，`import` 即可（已实测）。渲染进程仍是标准 Web 技术栈，规划里「Web 技术栈复用度」的诉求同样满足。
- 附带的兼容性收益：Electron 38 起默认 `--ozone-platform=auto`，在 wayland 会话下原生运行（本机 niri），不需要 XWayland 兜底。

**开发期形态（已定型为「双适配器」，不再是「先写一个、收尾换掉」）**：传输层从第一天就是 `Transport`
接口的两个实现——生产 = preload/IPC（已实现并跑通），开发 = 本地 HTTP/SSE（壳，S1 接）。两者共用同一份
channel 契约，故 renderer 代码 100% 复用：开发期用「系统 Node 跑内核 + 浏览器开 localhost」迭代（改一行
刷新即可，不重启 Electron、不占 200MB 二进制的加载时间），**交付形态仍是 Electron**。
「先写 WebSocket、收尾再换 IPC」不是切换而是重写——这条纪律已写进 `src/contract/transport.ts` 的文件头。

#### 3.2.1 DB 浏览器的两层语义（缺口 3 的设计取舍）

缺口 3 落地时定下三条，studio 的查看器线按此实现：

- **两种视图分工明确**：作者视图（`filter="none"`）能翻任意表（含包自定义表、含 phases/directives/data_status 这些作者面）；冒险视图（`user-related`）**只列内核表**并按既有可见性规则净化。表清单本身也按视图收窄——包表名可能带剧情（`xx_secrets`），列出来就是泄漏。
- **包自定义表在冒险视图下默认拒绝**（抛 `TableNotVisibleError`，不是给空页）：内核无从判断包表的可见性语义（包表里很可能存着玩家不该知道的事实），默认放行等于给冒险视图开后门。给空页则会与「这张表真的没有行」混淆。要让包表进冒险视图，需要作者在包里**显式声明可见性列**（如 `<表>: { npc_column: owner_npc_id }`）——属后续项，等真有包需要时再做。
- **过滤在分页之前**（在 JS 侧做，不下推 SQL）：可见性规则是 JS 函数（相关集合、到访地点集），下推等于把规则抄第二遍，必然漂移。为防内存无界，扫描有上限（`TABLE_QUERY_MAX_SCAN`=10000）并返回 `truncated` 标记——**宁可告诉调用方「还有没扫到的」，也不静默给一页看起来完整的数据**。

一致性由测试钉住：对 npcs / locations / events / location_log / world_state / phases / directives / data_status 八张表，逐表断言「通用查询结果 == 既有视图方法结果」，两份规则漂移即变红。

#### 3.2.2 开关与钉的持久化（缺口 7/10 的设计取舍）

- **持久化落在 `story.meta.json`，事实源仍在 `story.ts`**：`persistAgents` / `persistPinned` 与 `readStoryMeta` / `writeStoryMeta` 同处一模块，避免 meta 的读写规则散成两处。
- **`agents` 是三态，不是两态**：`stylize` 缺省 = 「按规则自动」（显式 style / adventure / 卡包 defaultStyle 三条规则），写成布尔才是调用侧定死。故 `persistAgents` **只落显式给过的字段**——把 `undefined` 折成 `false` 落盘，等于把「自动」冻成一次快照，之后改卡包 `defaultStyle` 也不再生效。
- **续写复原，但显式传入优先**：`openStory({ agents })` / `openStory({ pinned })` 是调用侧当下的明确意图，不该被上次会话的记忆盖掉（命令行 `-agents` 与 studio 的开关面板都属这一类）。
- **垃圾值响亮拒绝，不猜**：`resolveAgentsFromMeta` 只认布尔，读到 `"yes"` 之类的值直接抛错——开关**没有安全的缺省**（模式有：非法值回落 creation 是安全的），猜错了会让作者以为关掉的 subagent 其实在跑。这与 `readStoryMeta` 对 `mode` 的宽处理是**刻意不一致**的。
- **校验 → 落盘 → 重建，顺序不能换**：`setAgents` 先校验形态与模式预设组合，再落盘，**最后**才重建 runtime。若先重建、后校验失败，旧实例已 dispose，调用侧拿着废引用却不知道自己错在哪。这也解释了为什么重建不放在 runtime 层——runtime 只管「校验 + 持久化 + 回调」，装配层收到回调后重建，避免 runtime 反向依赖装配层。
- **空钉列表落成字段缺失**：`pinned: []` 与「没有这个字段」同义，meta 保持干净；读的时候两者都得到 `[]`。
- **读不懂的 meta 一律拒绝覆盖**：与 `saveSettings` 同一条纪律——宁可不写，也不把用户的东西抹掉。这里写的是一份决定「重启后跑不跑 subagent」的记录，静默丢失比报错有害得多。

##### 附带修掉的既有缺陷：`--resume` 会静默造新故事（已修）

写缺口 7 的测试时撞出来的，**与 7/10 无关，是既有问题**。

病根是 pi 的 session 文件**懒写**——只有故事里存在消息时才落盘。无开场白的故事（无包新故事就是这种）没有任何消息，文件从未写过；此时 `getSessionFile()` 仍返回一个路径，而 `openStory({ resume })` 把它喂给 `SessionManager.open`，pi 的 `_setSessionFile` 走「文件不存在 → `newSession()`」分支，**生成全新 sessionId**。于是「续写」变成「打开另一个新故事」，用户原来的库被撇在一边，且不报错——静默 + 看起来正常，最坏的一类失败。

`openStory` 现在设两道闸（都是响亮拒绝，不是把 pi 的兜底当正常路径）：

1. **`resume` 路径必须存在**；不存在直接抛错并指向 `listStories`（正常取 `sessionFile` 的入口）。
2. **纵深防御**：session 文件在、但其 sessionId 指向的故事目录不存在 → 也拒绝。否则 `openStoryDb` 会就地把目录建出来（它有建库语义），「续写」同样沦为「造一个空故事」。

判据不取「是否像 session 文件」——版本校验与 header 解析交给 pi（坏文件在那里会抛错），这里只堵「压根没有这个文件 / 目录」。两条都有测试与变异验证（各自去掉即变红）。


#### 3.2.3 pipeline 成对事件（缺口 6 的设计取舍）

- **`phase` 可选、缺省即 `end`**：历史 `pipeline-events.jsonl` 里没有这个字段，读旧日志必须当 `ok`/`durationMs` 齐备的结束事件看。故类型上是 `phase?: "start" | "end"`，消费侧统一写 `e.phase ?? "end"` —— **不迁移旧日志**，也不需要迁。
- **成对由 `stage()` 保证，不靠调用侧自觉**：`end` 落在 `finally` 里，成功 / 抛错 / 中止三条路径都会收束。若让每个调用点自己记得 `record`，迟早漏掉某条路径，而那条路径上的阶段就永远显示「在跑」——这正是缺口 6 要消灭的现象。
- **`endFields` 是回调不是对象**：`attempt` / `usage` / `outputChars` 只有阶段跑完才知道。传对象就得先跑再拼，等于把 `start` 也推迟到跑完，退回缺口 6 的老样子。
- **观测设施不得成为故障源**：`endFields` 与 `record` 都包在 `try` 里。若 `endFields` 抛错穿透 `finally`，它会顶掉 `fn` 的真实结果或原始异常——观测代码改写了被观测行为，这是不能接受的。故 `endFields` 抛错只作废它自己提供的字段，`end` 照落。
- **轮级（narrator）另有一层兜底**：整轮的 `start` 在轮首落，但只有「拒绝轮」和「正常轮末」两条显式 `end`。中止（`TurnAbortedError`）、subagent 炸、磁盘错都到不了这两处，故 `runTurnInternal` 的 `catch` 在异常透传前补一条 `ok:false` 的 `end`。没有它，一次中止就会让界面永远停在「生成中」——用户看到的是「卡死」，真相是那一轮早就抛了。
- **阶段粒度，不是 attempt 粒度**：重试是阶段内部的实现细节。界面该看到「data 段在跑」，不是「第 3 个 NPC 的第 2 次重试」。故重试次数 / 用量 / 输出规模挂在 `end` 事件的字段上（`endFields`），不再逐 attempt 落终态事件。**代价**：以 `pipeline-events.jsonl` 做逐 attempt 统计的外部脚本需改口径（`summarizePipeline` 就是为此提供的规范入口）。
- **`summarizePipeline` 是纯函数，不读盘**：调用侧把事件传进来（CLI 传内存事件，studio 传读出的 JSONL），便于层 1 断言。配对规则两条要紧：只闭合**同轮次**的 `start`（上一轮的遗留 `start` 不该被本轮的 `end` 收掉，否则谎报完成）；新的 `start` 覆盖未闭合的旧 `start`（重试 / 进程被杀的场景不卡在陈旧的 `start`）。


#### 3.2.4 提示词写口的层级边界（缺口 5 的设计取舍）

- **能写 global、不写 pack，分界线是「这是谁的产物」**：global 层（`~/.tavernpi/prompts`）是**本机作者的全局偏好**——作者对自己机器上的文件有完全处置权，改它只影响自己。pack 层是**别人分发的产物**：在这里改写等于偷改分发内容，作者下次更新卡包就冲突。

  > ⚠️ **有一个容易踩的优先级后果**：覆盖链是 `story > pack > global > builtin`，**pack 压过 global**。所以给一个装了卡包的角色设了全局提示词却"没生效"，是**正常现象**而非 bug——排查要看覆盖链，别猜。已写成测试钉住（`pack 压过 global` 一条 + `不装卡包时 global 才接管` 一条）。
  >
  > 因此"想让全局偏好对所有情况生效"这个愿望本身是有前提的：该角色**没有**被任何装载的卡包覆盖。要真做到全局强势，得改覆盖链的语义（那会让卡包难以覆盖内置提示词），不在本缺口范围内。
- **`clearXxxOverride` 返回 boolean，story 层不返回**：这不是不一致，是后果不同。global 层一般直接盖住 builtin，删掉与没删掉的行为差异很明显；调用侧无法从"没报错"里分辨"真删了"和"本来就没有"，所以说清楚。story 层原本不返回是历史形态，语义上并不冲突。
- **写口失败原样抛，不吞**：这是"观测设施不得成为故障源"的反面纪律——写提示词是**作者的主动行为**，"以为改好了、下轮还是旧提示词"比报错有害得多。故只有 `clear` 的"文件不存在"是预期分支（返回 `false`），其它失败（父级是普通文件、权限不足）一律抛。
- **`globalDir` 显式可选，缺省 `defaultGlobalPromptsDir()`**：同一个理由的两半——（a）测试要能把它指到临时目录，否则写测试就真去动用户的 `~/.tavernpi/prompts`；（b）"多份全局配置"的场景本来就是可能的需求，与 `loadPrompt` 的 `dirs.globalDir` 保持同一语义。

变异验证三条（全红）：去掉 `assertValidRole`／`clear` 恒返回 `true`／**runtime 里把 `globalDir` 硬编码成默认家目录**。第三条尤其要紧——那个 mutant 会写进用户真实的 `~/.tavernpi/prompts`，把它指回 `runtimePromptDirs.globalDir` 的**唯一护栏就是测试**。


#### 3.2.5 换包与热更新的分界（缺口 10 余项的设计取舍）

- **先分清「热更新」与「换包」，否则会重复造轮子**：包内**文本**（集合条目 / story.yaml / 提示词）本来就是热的——`PackCache.getPacks()` 每次调用重扫 mtime，而 narrator 每轮调它，作者改文本**下一轮即生效**，不需要任何 API。`setPacks` 管的是**增删整个包**（改的是「装载哪些包」，不是「包里写了什么」）。这条区分不写下来，后来者很容易以为「改包要重建 runtime」而把热路径也做重。

- **为什么换包必须重建 runtime，不能只换 cache**：`packDirs` 在两处被冻结成**构建期常量**——① `runtimePromptDirs.packDirs`（提示词 pack 层解析）；② `collectCodePackEntryPaths` 读 `story.meta.json` 拿 `additionalExtensionPaths`（代码包 extension 注册进主叙事 session）。两者都只在 `createStoryRuntime` 里算一次。注意 ② 是硬约束：extension 的工具是**建会话时**注册进 pi 的，实例建好后改不了。

- **`PackCache` 必须重建，不能沿用**：新包的 mtime 指纹从未被记录过。沿用旧实例会让首次 `getPacks()` 拿到「好像没变化」的旧快照。这与「热更新时保留 cache」不冲突——那是同一批目录内的内容变化。

- **装配态的懒建与删除**：`assembly.packs` 在 `packDirs` 为空时是 `undefined`（无注入形态，narrator 渲染「（无世界包注入）」）。故「无包 → 有包」必须**建出来**，「有包 → 无包」必须 **delete**。只更新 `packDirs` 而不管这个对象，会出现「注入开着但包已移除」或「包已装载但注入还关着」——两边都测过，各对应一个 mutant。

- **三段式顺序沿用 setAgents：加载校验 → 落盘 → 重建**。`loadPacks` 会做 zod strict / 引用完整性 / 前缀扫描 / id 冲突，且**收集全部问题一次性抛**。顺序不能换：先重建再校验的话，旧实例已 dispose，调用侧拿着废引用还不知道自己错在哪。

- **空列表落成字段缺失（与 pinned 同规）**：`packs: []` 与「没有这个字段」同义，meta 保持干净。这一条**顺带暴露了一处类型不诚实**：`StoryMetaFile.packs` 原本是必填，必填会逼着实现要么写假的 `packs: []`、要么用类型断言糊过去。已改为可选，并把唯一一处无保护的消费点（assembly 的 `meta.packs.map`）补上 `?? []`。

- **只改装载关系，绝不删磁盘文件**：移出一个包只是让**这个故事**不再装载它。这条写成了显式测试——包目录与包内文件在减包后必须原样存在。

- **测试判据要避开机器状态**：初版测试断言减包后 `effectiveLayer === "builtin"`，在本机红了——因为这台机器上存在 `~/.tavernpi/prompts/narrator.md`（缺口 5 的产物），合法落点是 `global`。**断言绝对层级等于把测试绑死在某台机器的家目录状态上**。改为断言「pack 层不再是生效层 + pack 层无候选路径」，与家目录无关。真 CLI 端到端也独立复现了同一件事（加包 → pack；减包 → global）。

#### 3.2.6 可见性缓存的新鲜度（缺口 12 的设计取舍）

- **缺口描述里的补救已过期，别照做**：原文写「若将来要作者视图需扩映射（`none` / `user-related` 之外再加一种）」。但 `filter="none"` **就是**完整作者视图——能翻任意表、含 phases/directives/data_status、不净化。要「作者视图」不需要扩映射，直接用 `none`。真正该修的另有其事。

- **真正的残余缺陷是「新鲜度只靠约定」**：`resolveRelatedNpcSet`（相关 NPC 集）与 `resolveVisitedLocationIds`（到过地点集）原先在**构造时**解析一次并冻结。既有消费方**碰巧**都按查询现建视图（`assist.ts` 的 `viewFactory` 每次 `execute` 现建；`m6-cli` 的 `/npc`、`/status` 每次现建），于是新鲜度是对的——但它**没有任何机制保证**：谁哪天把视图提到循环外复用，就会静默读到陈旧可见性，且不报错。这类「靠大家记得」的正确性迟早破功。

- **改为惰性 + 缓存，并给 `refresh()`**：首次访问某集合时才解析，之后缓存；`refresh()` 作废全部缓存（三个集合：相关 NPC、到过地点、可见事件 id），下次访问重算。这样：
  - **构造不再付解析开销**——`resolveMentionedNpcIds` 要扫遍**每一轮**的 `narrative_text`，对只看一张表的调用方本是纯浪费。惰性让「建了但没查」= 零成本。
  - **对外行为不变**：不 `refresh()` 仍是旧可见性。这不是 bug，是惰性的**语义**——测试里刻意钉住（「不 refresh 就还是旧可见性」一条），以免将来有人误以为该自动刷新而改坏它。
  - **复用实例的场景有了明确规则**：「查之前想要新鲜的，就刷一下」，规则从调用方脑子里落到类型上。`refresh()` 与「每次现建视图」**等价**，前者是给「想留着实例」的场景省重复构造。

- **`refresh()` 必须连事件 id 缓存一起清**：`eventIdCache` 也是可见性判据（`queryTable(event_npcs)` 用它判事件是否可见）。变异测试发现这条**没有测试覆盖**——「refresh 不清 eventIdCache」的变异体是绿的。补测试后转红。这是本缺口最有价值的产出：变异测试揪出了我自己测试里的空洞。

- **变异验证**（5 个变异体全红，基线绿）：① `relatedSet` 每次重算 → 「同一引用」断言红；② `refresh` 不清相关集 → 移动 NPC 后断言红；③ 不清到过地点集 → 对应断言红；④ 不清事件 id 集 → 补测后红；⑤ `none` 模式也解析集合 → 省开销断言红。

- **调用侧注释同步更新**：`assist.ts` 的 `createAssistTools` 文档注释原写「每次 execute 现建…开销小」，现补上「等价地可 `refresh()`」——否则注释会误导后来者以为只有重建一条路。


### 3.3 数据源归属（决定 studio 的数据流）

**核心判断：阅读流的正文事实源是 `story.db` 的 `turn_log`，不是 pi 的 session 转录。**

证据：`TurnLogRow`（`db/types.ts:179-186`）字段为 `turn_seq` / `session_entry_id` / `user_input` / `narrative_text` / `raw_text` / `warnings` —— `narrative_text` 是终稿，`raw_text` 是润色前稿。而 `TurnResult`（`runtime.ts:466-499`）只在当轮即时返回。

这条判断的收益：`narrative_text` 落在 DB 里，而 DB 随快照恢复一起回退（回溯 = 导航 + 恢复快照），所以**阅读流与故事树天然一致**，不需要 studio 自己在 session 转录里重建「这条分支到第几轮」的逻辑。反之 session 转录里存的是草稿链（含被 stylize 丢弃的稿、被 story 打回重写的稿、swipe 的旧稿），直接渲染会出现「显示的不是定稿」。

| UI 区域 | 事实源 | 取数方式 |
|---|---|---|
| 阅读流正文 | `story.db.turn_log.narrative_text` | `DbReader.getTurnLog()`（分页） |
| 润色前原稿（对照/差异视图） | `turn_log.raw_text` | 同上 |
| 玩家行动行 | `turn_log.user_input` | 同上 |
| 分支/树 | session 转录 | `SessionManager.getTree()` / `getEntries()` / `getBranch()` |
| 回溯 | session 导航 + 快照钩子 | `session.navigateTree(id)`（已实测于 CLI，`m6-cli.ts:478`） |
| **当前生成轮**的流式正文 | pi session 事件 | `session.subscribe()` → `message_update` / `text_delta`（**仅临时展示，轮末用 `TurnResult.narrativeText` 覆写**） |
| 入库状态 / 告警 | `data_status` / `turn_log.warnings` | `DbReader.listDataStatus()` |
| 时钟 / 时间线 | story 库 | `getClock()` / `listEvents()` / `listTimeLog()` |
| NPC 卡（含模式过滤） | story 库 + 视图 | `createDbView(reader, MODE_PRESETS[mode].dbViewFilter)` |
| pipeline 观测 | `pipeline-events.jsonl` + 内存订阅 | `eventLog.on()`（含 `durationMs` / `usage.costTotal`） |
| 模式 / 卡包 | `story.meta.json` | `readStoryMeta()` / `runtime.mode` |

**流式与定稿必须分离**：stylize 会润色、story 可能打回重写，流式草稿与终稿可以不同。CLI 的做法是把流式尾巴只画在临时活动行上、正文只从 `TurnResult` 打一次（`m6-cli.ts:283-334`）。studio 必须沿用同一条纪律：**打字机效果写进「生成中」气泡，轮末整体替换为定稿**。

## 4. 架构设计

### 4.1 进程布局

```
Electron main 进程（唯一内核宿主，Node 24.21）
├─ SessionManager / StoryDb / SnapshotsDb   ← 每故事一套，活跃故事同一时刻一个
├─ StoryRuntime                              ← turn pipeline、subagent、快照钩子
├─ InteractionBroker handler                 ← 转成 IPC 请求发给 renderer
├─ PipelineEventLog.on(...)                  ← 广播阶段事件
└─ ipcMain.handle / webContents.send ────────┐
                                             │ contextBridge（preload，窄接口）
Electron renderer 进程（纯 UI，无 nodeIntegration，sandbox: true）
└─ 阅读流 / 树 / DB 浏览器 / 编辑器 / 配置面板
```

不建议把内核放进 `utilityProcess`：IPC 成本换不到隔离收益，且违背「同进程嵌入」的既定决策。内核异常会带走整个 app（CLI 是单次会话，代价小；GUI 要补全局错误边界 + 重开 runtime 的恢复流程），这是必须显式处理的代价。

### 4.2 传输层契约（草案）

方向一（renderer → main，请求-响应）：

| channel | 载荷 | 内核调用 |
|---|---|---|
| `story:list` / `story:create` / `story:open` | root / packDirs / mode / resumePath | `listStories`（待补）/ `createStory` / 装配 helper |
| `turn:run` / `turn:abort` / `turn:swipe` | input / force / signalId | `runTurn`（`signal` 待补）/ `swipe` |
| `tree:navigate` / `tree:fork` | entryId | `session.navigateTree` / `forkStoryDb` + 重建 |
| `db:query` | table / filter / page | 通用查询（待补） |
| `db:write` | Changeset | `runtime.trustedWrite`（唯一合法写路径） |
| `prompts:read` / `prompts:write` | role / layer / content | `resolvePromptChain` / `setStoryOverride` |
| `mode:set` | mode | `runtime.setMode`（adventure 锁定错误要原样呈现） |
| `settings:read` / `settings:write` | models / thinking | `loadSettings` / `saveSettings`（待补） |
| `interaction:respond` | requestId / payload | 兑现 broker 的 pending Promise |

方向二（main → renderer，单向推送）：`turn:delta`（流式增量）、`event:pipeline`（阶段事件）、`turn:done`（含终稿与阶段耗时）、`warning`、`interaction:request`、`restore:done`（回溯后的时钟/事件数）、`story:changed`。

**序列化纪律**：IPC 是结构化克隆，内核对象不能直接过界。pipeline 事件本身就是 JSON-safe 结构（`events.ts:16-32`）；pi 的 session 事件带累计 `partial` 字段不可直接传，需经 pi 自带的 `toJsonEvent`（`modes/json-event`，去 `partial`、补 `usage`）转换后再发。**这条能省掉一整套自制事件 DTO**。

### 4.3 接线层：内核已抽 `openStory()`（原「建议」已落地）

现状（2026-09-18 起）：从「session 文件 / 新故事」到「可跑的 StoryRuntime」的装配已收进内核
`packages/core/src/assembly.ts`，`m6-cli` 改为消费它——app 层里那约 150 行装配已删除。四个导出：

```ts
openStory(opts: OpenStoryOptions): Promise<OpenedStory>          // 新建 / 续写
rebuildRuntime(opened: OpenedStory): Promise<OpenedStory>        // 改 subagent 开关后重建
forkFrom(opened: OpenedStory, entryId: string): Promise<ForkInfo> // 分叉（含重放卡包迁移）
resolveStylizeEnabled(opened: StoryAssembly): boolean            // stylize 三态判定
```

收进去的踩坑细节（studio 若自己复刻，必然与 CLI 漂移）：

- 续写路径：`SessionManager.open(file)` → `storyDir = <root>/<sessionId>` → 开两个库 → 从 `meta` 恢复 `packDirs`；
- 新故事路径：`createStory()` 一次拿到 sessionManager + storyState；
- 依赖装配：`loadSettings()` → `PromptLayerDirs{globalDir, packDirs}` → `ModelRuntime.create()` → `eventLog`；
- stylize 的三条自动开启条件（显式 `--style` / 卡包 `defaultStyle` / adventure 强制）；
- fork：祖先链 → `createBranchedSession` → **重放卡包迁移**（漏了这条 fork 产物只有内核表）→ 继承 meta →
  重建 cache → dispose 旧 runtime 与两个库 → 重建 runtime；
- 改开关要重建 runtime（开关在创建时固化）；
- 轮中交互 handler 是实例级的，每次重建**自动重挂**（漏挂的后果是卡包工具静默降级）。

状态容器语义：`OpenedStory` 是**原地更新**的可变容器——上述函数会替换其中的 runtime / storyState /
eventLog / packs，调用侧持有的引用始终有效。

### 4.4 传输层与渲染边界（新增纪律）

- **传输层从第一天就是可替换适配器**：`packages/studio/src/contract/` 定义 channel 名与载荷类型
  （`ChannelMap` / `PushMap` / `Transport`），生产适配器走 preload/IPC（`src/main/transport-ipc.ts`，
  已实现并有单测），开发适配器走本地 HTTP/SSE（`src/dev/transport-ws.ts`，当前是**大声抛错的壳**——
  它的价值依赖 main 侧 handler 与 renderer 应用，两者尚未接线）。
- **渲染进程不得值导入内核**：模式过滤、唯一写路径、快照恢复都在 main 侧内核实例里。允许
  `import type`（类型剥离不留运行时代码）。判据是 `packages/studio/test/boundary.test.ts` 的源码扫描
  ——架构边界必须是机器判据。
- **载荷形状不预先发明**：只登记内核已有 API 支撑的 channel；缺口 3（通用只读查询）这类还没实现的能力
  不提前设计接口，接口等实现。

### 4.5 游玩主线的实现要点

- **打开故事**：`turn_log` 分页渲染历史（长故事需虚拟滚动）；每条含行动行与叙事正文，`warnings` 与 `data_status` 作为低调的角标。
- **提交一轮**：`turn:run` → 立即建「生成中」气泡 → 订 `session.subscribe` 打印式追加文本 + 订 `eventLog.on` 显示当前阶段（story/npc/stylize/data 的阶段词可由事件 `role` 映射，CLI 已有映射表 `m6-cli.ts:237-263`）→ 轮末用 `TurnResult.narrativeText` 覆写气泡，附带阶段耗时与成本。
- **输入被拒**：catch `InputRejectedError`，把 `reason` / `suggestion` 呈现为可编辑的驳回提示（`/!` 强制提交做成「仍然提交」按钮，对应 `runTurn(input, {force: true})`）。
- **树 / 回溯 / fork / swipe**：直接包 `navigateTree` / `forkStoryDb` / `swipe`；回溯完成后刷新时钟与事件（CLI 的 `renderRestore` 语义）。注意 `isStreaming` 期间禁止导航与 swipe，内核会抛错。
- **创造模式专属**：`/plot` 剧情大纲指令需要一条独立的输入渠道（`listDirectives` 读现状）。

## 5. 分发、许可与版本

- **内核分发形态（已定）**：studio 与内核**同仓库**，故 studio 用 workspace 依赖即可——
  `"@tavernpi/core": "0.0.0"`，npm 自动软链到 `packages/core`（实测 `node_modules/@tavernpi/` 下四个包
  均为软链）。**npm 发包推迟**：内核仍是 `private: true` / `0.0.0`，且以「TS 源码直发 + 无 files 白名单
  + tarball 里没有 LICENSE」的形态发上公共 registry，等于把半成品形态冻结成公共契约。等到「studio 之外
  也需要装内核」或内核 API 定型时，再单独做一轮发行工程（版本号统一 / files 白名单 / LICENSE 随包 /
  构建产物或源码直发的取舍 / registry token）。
- **「源码直发」的机器判据已就位**：studio 能直接吃 `.ts`，靠的是 Node 的类型剥离（Electron 44 = Node
  24.21 默认开启）；代价是内核不得引入 `enum` / `namespace` / 构造函数参数属性。这条**不是靠自觉**——
  `tsconfig.base.json` 已开着 TS 5.9 的 `erasableSyntaxOnly: true`（core 的 tsconfig 直接 extends 它），
  一旦有人引入不可擦除语法，`npm run typecheck` 立刻失败。原「建议加 lint」一项据此销账。
- **GPL 连带**：内核 GPL-3.0-or-later，studio 同进程嵌入并对外分发时整体须 GPLv3 兼容并提供源码（自用不触发）。这条已记在 `创作规划.md` §3，此处只是重申：**它约束的正是 Electron 形态**（同进程嵌入 = 单一作品），若将来要闭源分发，得回内核侧改许可或双授权。
- **自动更新**：Electron 侧走 `electron-updater`，但本机 GitHub 不通（§1），更新源必须自建或走镜像。这是 Electron 路线里**唯一尚未实测清零**的运营风险，S0 收尾前应连同二进制镜像一起验证一次。

## 7. 风险清单

| 风险 | 影响 | 处置 |
