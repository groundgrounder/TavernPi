# tavern studio 创作规划

> tavernpi 内核的 GUI 外壳：**与内核同仓库、独立包**（`packages/studio`，包名 `@tavernpi/studio`）。
> 拆成独立仓库的正当条件是「内核 API 定型且有 studio 之外的消费者」，届时迁移只是一次 git 操作；
> 在那之前跨仓只会让「改内核 → 发版 → 升依赖 → 适配」的往返每天发生一次。
> 类比浏览器之于 Chromium：故事引擎全部能力在内核，studio 是面向创作与游玩的图形外壳。
> 本文档是 studio 项目级事实来源。对内核的依赖以 `@tavernpi/core` 的导出 API 为唯一契约边界。
>
> **文档结构约定**：本文档只承诺 **UX 层契约**（用户能在 GUI 里做什么）；引擎行为契约（回溯一致性、模式强制、零事实漂移等）以内核实现与其导出 API 为准，本档不转述、不复制——避免双事实来源漂移。

## 1. 定位与形态

- **嵌入方式（已决策）**：以 npm 库形式同进程嵌入 tavernpi 内核，不走 RPC。同仓库 workspace 已解决
  「装不上内核」的问题：studio 依赖写 `"@tavernpi/core": "0.0.0"`，npm 自动软链到 `packages/core`。
- **形态选型（S0 定案）：Electron**。Tauri 否决——宿主是 Rust，进程内没有 Node 运行时，同进程嵌内核
  要么变成 sidecar + IPC（= RPC，违背已决策），要么嵌替代运行时（内核依赖 `node:sqlite` / `node:fs`
  同步 API，风险不可控）。依据与实测见 `技术考察.md` §1–§2。
- **渲染层选型：React + Vite + TypeScript**。判据是成熟件覆盖度而非偏好：长叙事流的虚拟滚动、
  故事树、DB 表格、表单密集的编辑器线都有现成件；换更轻的框架要自己写其中两样。
- **传输层（纪律）：从第一天就是可替换的适配器**——生产走 preload/IPC，开发走本地 HTTP/SSE
  （浏览器直开 + 热刷新，不必反复重启 200MB 二进制）。两个适配器共用同一份 channel 契约
  （`packages/studio/src/contract/`）。「先写 WebSocket，收尾再换 IPC」不是切换，是重写。
- **不做**：任何故事引擎逻辑（turn pipeline、subagent、快照、校验全部在内核）；不自己实现模式——
  三模式是内核级强制预设，studio 只呈现与提供配置入口。UI 侧绕过模式在架构上不可能，因为过滤与
  校验在内核查询层。

## 2. 能力（契约：给用户）

以下为 studio 对用户的承诺面；各能力的底层行为契约归内核实现，本节不转述。

- **游玩界面**：叙事阅读流、分支/swap 操作、模式对应的输入渠道（创造模式含剧情大纲指令输入；生存/冒险模式的输入校验反馈 UX）、长轮的**中止**按钮（内核 `runTurn({ signal })`）。
- **编辑器**：
  - 世界观/世界书条目、角色卡（轻量格式，由内核卡包加载器定义）、卡包管理；
  - NPC 设定：对 DB 中特征/记忆/关系的直接编辑——必须走内核写入 API，禁止绕过；
  - 提示词编辑器：可视化编辑内核提示词分层的各层（内置/全局/卡包/故事级），显示当前生效层与覆盖链。
- **查看器**：
  - 故事树（浏览/回溯/fork/clone，回溯经内核 `navigateTree` 挂钩触发快照恢复）；
  - DB 浏览器（模式过滤由内核查询层执行，studio 不过滤）；
  - 时钟与事件时间线；
  - turn pipeline 运行观测（各 subagent 的输入/输出/耗时/成本，来自内核 pipeline 事件流）。
- **agent 配置界面**：各角色模型、thinking level、启用开关；模式管理（创造/生存/冒险）。

## 3. 对内核的依赖（协作契约：对内核项目）

依赖 `@tavernpi/core` 的导出 API：故事生命周期（创建/加载/分支/回溯）、带模式过滤的 DB 查询、
受信任的 DB 写入 API、提示词分层管理、agent/模型配置、模式管理、pipeline 事件流。

纪律：

- **契约单一来源**：channel 名与载荷类型只在 `packages/studio/src/contract/` 定义一次，main 侧与
  renderer 侧都从这里 import；类型直接引用内核导出类型（`import type` 会被类型剥离，不会把内核
  打进渲染包），两边各抄一份必然漂移。
- **渲染进程不得值导入内核**：模式过滤（`DbView`）、唯一写路径（`trustedWrite`）、快照恢复都在 main
  侧的内核实例里，渲染进程只要能值导入内核就等于把信任边界搬到了页面上。允许 `import type`。
  这条由 `packages/studio/test/boundary.test.ts` 扫源码钉住——架构边界必须是机器判据，不能只写文档。
- **装配知识归内核**：从 session 文件/新故事到可跑 runtime 的接线（含 fork 重放卡包迁移、开关变更
  重建、交互 handler 重挂）由内核 `openStory` / `rebuildRuntime` / `forkFrom` 提供，studio 与 CLI
  共用同一份。studio 侧发现缺能力就回提内核，不在 studio 内造引擎逻辑的补丁层。
- 内核 API 语义变更走版本化，studio 升级内核时显式适配，不静默跟随。
- **许可证连带约束（本约束来自内核许可，非 studio 可协商项）**：内核为 GPL-3.0-or-later（见内核仓库 `LICENSE`）。copyleft 不认仓库边界——studio 同进程嵌入 `@tavernpi/core` 并**对外分发**产物时，studio 整体须以 GPLv3 兼容条款发布并提供对应源码（仅自用、不分发则不触发）。若将来需要保留闭源或商业分发路径，必须回到内核侧解决（双授权或调整内核许可），不在 studio 侧绕过。

## 4. 里程碑

依赖按**内核缺口编号**记（见 `技术考察.md` §3.2），不按内核里程碑记——内核 M0–M6 已全部验收通过，
「S1 依赖 M2」那类写法早已不是真约束，真钉子是缺口清单。

| 里程碑 | 内容 | 依赖（内核缺口编号） | 验收判据 |
|---|---|---|---|
| **S0 选型** | Electron 定案 + 环境冒烟（`spike/s0-smoke.cjs` 全绿） | 无 | 已完成。**待补**：空壳 app 内真跑「创建故事 → 发一轮（真 LLM）」 |
| **第 0 刀 内核补口** | 缺口 1 中止 / 2 settings 写 + thinking / 4 故事枚举 / 8 装配 API | 无（内核侧工作） | 已完成（2026-09-18）：`openStory`/`rebuildRuntime`/`forkFrom`/`listStories`/`runTurn({signal})`/`saveSettings` 落地，测试 353 → 395 全绿 |
| **S1 壳与游玩主线** | 故事列表/新建/打开、阅读流、输入、流式渲染、中止、树/回溯/fork/swipe | 1、4、8（**均已补**） | 一轮真实叙事在 GUI 里流式呈现且终稿正确；回溯后 DB 与时钟回退可见（判据取盘上 `story.db`，不取界面文本） |
| **S2 查看器线** | 故事树可视化、DB 浏览器、时钟与事件时间线、pipeline 观测面板 | 3（通用只读查询）、6（阶段「开始」事件） | DB 浏览器能翻任意内核表与卡包自定义表，冒险模式下看不到非相关 NPC |
| **S3 编辑器线** | NPC 设定（走 `trustedWrite`）、卡包管理、世界书/角色卡、提示词分层编辑器 | 5（global 层提示词写）、9（卡包校验模块导出）、10（pin/启停持久化） | 编辑 NPC 特征后落库可见；提示词覆盖链显示出「当前生效层」 |
| **S4 模式与配置 UX** | 三模式呈现与切换、输入校验反馈、`/plot` 入口、agent 配置界面 | 2（**已补**）、7（开关持久化） | 三模式切换的非法组合被内核拒绝并原样呈现；改模型/思考等级后重启生效 |

里程碑对齐原则：studio 里程碑不早于其依赖的内核缺口被补齐；缺口 3/5/6/7/9/10 都是小改造（补一个
写函数、加一个白名单查询、加几个 meta 字段），建议并行开一条「内核补口」线，避免 S2–S4 空转。
